# Пандитджи

**Личная ИИ-система для отслеживания здоровья, практики и обучения**

Адриан, итог разговора 13 мая 2026 (версия 2)

---

## 1. Что строим и зачем

Личная ИИ-система, которая помогает структурировать жизнь без необходимости вести дневники и записывать всё вручную. Адриан **не любит записывать**, поэтому главный принцип архитектуры:

> **80% данных приходит автоматически, 20% — минимум усилий (одна кнопка)**

Цель — единый утренний экран, который:

- Показывает биометрику за прошедшие сутки (сон, HRV, восстановление, вес, тренды)
- Показывает астрологический контекст дня (тити, накшатра, текущие даши, транзиты)
- Показывает данные вчерашней джапы (Muse): mind wandering, концентрация
- Даёт сегодняшние задачи: события календаря, шлоки на повторение, слова хинди
- Через ИИ-слой выдаёт инсайты — реальные корреляции на накопленных данных

Контакт с системой утром — **1–2 минуты**. Микро-чек-ин (несколько кнопок), просмотр расписания, шлока/слова.

## 2. Имя системы

**Пандитджи** (одно слово)

Передаёт роль (знаток, к которому обращаешься за знанием), уважительное в самом обращении, не присваивает имя Бога или ачарьи, культурно естественно для Индии. Технически в коде/URL используется `panditji` или `pj`.

## 7. Архитектура передачи данных Muse — детально

**У Muse нет публичного облачного API**, и Mind Monitor на Android **не** умеет автозагрузку в Google Drive. Поэтому используется share-intent через Telegram:

```
Утром:
  1. Адриан надевает Muse, открывает Mind Monitor (Android, бесплатное)
  2. Жмёт Record, делает джапу 1–2 часа
  3. Жмёт Stop
  4. Mind Monitor предлагает share-меню — Адриан выбирает Telegram → @panditji_bot
  5. CSV прилетает в Telegram-бот как документ

Дальше (автоматически):
  6. telegram-webhook принимает .csv, gzip'ит, кладёт в Supabase Storage
  7. parse-meditation-csv разбирает CSV → сессионные агрегаты + timeline 30 сек:
     - Перевод Bels (log PSD) → линейные мощности → относительные % от total
     - Сессионные медианы alpha/theta/beta + AB-index
     - Theta по третям сессии (для расчёта углубления)
     - Signal-shift детектор (ловит «съезд» повязки — HSI этого не видит)
  8. Бот спрашивает 5 вопросов: тип / круги / место / отвлекали / самооценка
  9. После подтверждения circles — compute-meditation-circles:
     - Разбивка timeline на круги
     - Углубление (Theta last vs first), стабильность, longest calm (P75)
     - Авто-теги, шаблонные интерпретации, фазы
     - Триггерит recompute baseline + enrich Whoop
  10. Сессия видна в PWA: /meditation/sessions.html?id=<uuid>
      + виджет на /morning.html со сводкой
```

**Где это реализовано** — домен `meditation/`, см. `domains/meditation/README.md`.

**Режимы использования Muse:**

- **Дневная джапа:** Mind Monitor (запись сырых данных в Пандитджи)
- **Сон:** официальное приложение Muse + Premium-подписка (Smart Alarm, Deep Sleep Boost, Sleep Assist)

**Ограничение:** Mind Monitor и официальное приложение не работают одновременно. Поэтому для джапы — Mind Monitor, для сна — Muse App. Данные сна экспортируем периодически (раз в неделю CSV из приложения).

## 8. Сон — что система реально даст

### Базовые метрики (Whoop, автоматически)

- Длительность сна, эффективность, время засыпания
- Стадии сна (глубокий, лёгкий, REM, бодрствование)
- Количество пробуждений
- Температура тела ночью
- HRV и ЧСС ночью
- Дыхательная частота и SpO2
- Sleep Performance (% от потребности)
- Recovery Score (0–100%)

### Дополнительно (Muse Athena ночью)

- Стадии сна с точностью EEG (не косвенно, как Whoop)
- Глубокий сон по дельта-волнам
- Sleep position tracking
- Deep Sleep Boost (тихие аудио-сигналы для усиления глубокой фазы)
- Sleep Assist (помощь при засыпании)
- **Smart Alarm с пробуждением в лёгкой фазе** — Muse Athena определяет фазу по реальной мозговой активности, точнее Whoop

### Связь джапы со сном (главный кейс)

Двусторонняя связь:

**Утренняя джапа ↔ предыдущий сон**
- Качество сна (Whoop + Muse) → качество утренней джапы (Muse)
- HRV ночи → mind wandering утром

**Дневная джапа ↔ следующий сон**
- Качество джапы → засыпание / глубокий сон / эффективность

**Через 2–3 месяца** появятся реальные паттерны:
- В какие дни недели сон хуже
- Как путешествия Москва–Индия сбивают сон, сколько дней восстановления
- Зимой в Москве и летом в Индии — разный профиль сна

### Утренний будильник

Smart Alarm на Muse Athena: задаётся целевое время (например, 4:30 для брахма-мухурты) и окно (15–30 минут до цели). Muse будит вибрацией в момент лёгкой фазы сна в этом окне.

## 9. Что система РЕАЛЬНО будет давать — без фантазий

### Прямые корреляции между автоматическими данными

**Сон → день:**
- Когда спал меньше нормы, какой ЧСС покоя на следующий день
- Поздний отбой → страдает HRV → страдает джапа
- Накопленный sleep debt → дневная нагрузка

**HRV → метаболизм:**
- В дни низкого HRV — какое давление утром (когда тонометр появится)
- В недели высокого HRV — какой вес и состав тела

**Вес → биомаркеры:**
- Висцеральный жир ↔ LDL, HbA1c, hs-CRP
- Тренд веса по сезонам и локациям

**Температура (Whoop) ранний сигнал:**
- Подъём температуры тела на 0.3°C во сне = ранний сигнал болезни за 1–2 дня
- Совмещение с падением HRV — двойное подтверждение

**Анализы крови → биометрика:**
- D-витамин ниже 30 ng/mL → средний HRV в эти месяцы
- LDL растёт → что параллельно происходит с весом и составом
- hs-CRP ↔ тренд HRV (воспаление ↔ восстановление)

### Корреляции с астрологией

Поскольку астрология вычисляется автоматически:
- HRV по фазам Луны
- Качество сна в Экадаши, Пурниму, Аштами
- Паттерны по тити / накшатре / йоге
- Влияние периодов даш на ЧСС покоя

Это **личные данные** для проверки астрологических концепций на собственном теле.

### Сезонность и геолокация

- Москва vs Индия — реакция тела на разные климаты
- Лето / зима — тренды веса, сна, давления
- Период муссона — влажность и сон
- Смог в Северной Индии — влияние на показатели

### Качество медитации (Muse) — реализовано

- **Углубление Theta** — рост Theta от первой трети к последней (`deepening_pct`)
- **Стабильность** — медиана Alpha/Beta индекса по сессии
- **Спокойные отрезки** — окна, где AB-индекс попадает в верхнюю четверть сессии (longest calm + count)
- **Авто-теги**: глубокое/раннее/обратное углубление, признаки сонливости, много блуждания, артефакт повязки, технические проблемы
- **Корреляции** (Spearman) с Whoop-данными: сон → углубление, recovery → стабильность; box-plot «отвлекали → углубление»
- **16-бинная нормализация baseline по позиции в сессии** — сравнимо для сессий с 12, 16, 24 кругами

Через 30+ сессий — личный baseline. Сравнение «сегодня vs ср. за 30 дней» по трём per-circle метрикам (Theta-кривая углубления, AB-кривая стабильности, Beta-кривая фона беспокойства).

### С добавлением микро-чек-ина

После 60+ дней с утренней «одной кнопкой»:
- «В дни, когда начинаешь сразу с джапы, Mind Wandering в среднем на X% ниже»
- «После вечеров с экраном глубокий сон на Y минут короче»
- «В дни высокого стресса HRV ночью ниже базы на Z единиц»

## 10. Что система НЕ даст

Чтобы не было ложных ожиданий:

- Не скажет, **почему** именно сегодня плохо спал (нужно знать, что делал — не записываем подробно)
- Не подскажет, **какая еда подняла LDL** (для этого CGM + дневник питания)
- Не оценит качество медитации по содержанию (Muse даёт состояние мозга, не суть практики)
- Не предупредит за неделю, что **завтра заболеешь** (только за 1–2 дня по биомаркерам)

Это **трекинг + аналитика**, не предсказание.

## 11. Зачем это всё носить — основные смыслы

1. **Раннее обнаружение** болезней, перегрузок, дрейфа здоровья (за 1–2 дня до симптомов через HRV, температуру)
2. **Объективный ответ** на «как я на самом деле?» — без субъективного «вроде нормально»
3. **Контроль LDL** в динамике, не от одного анализа в год
4. **Долгосрочный архив** на 5+ лет — серьёзная база для любого врача в будущем
5. **Объективный замер качества джапы** через Muse — главная личная задача Адриана
6. **Простая трезвость** — иногда система просто покажет «ты выгорел, ляг сейчас»

## 15. Эволюция микро-чек-ина

**Принцип:** каждая ручная переменная должна окупаться корреляцией. Если через 2 месяца переменная не даёт видимой связи с биометрикой — отключаем.

**Что точно работает (одна кнопка / 3-точечная шкала):**
- Самочувствие 😊/😐/😟
- Утренний паттерн (джапа сразу / телефон / другое)
- Вечерний паттерн (чтение / экран / тишина / лекция)
- Качество ночи по ощущениям
- День: лёгкий / средний / тяжёлый

**Что НЕ работает (любые попытки):**
- Подсчёт кругов джапы — забудешь / надоест
- Питание (что ел, сколько) — слишком сложно для «одной кнопки», для этого CGM
- Эмоциональное состояние словами — текст не работает долгосрочно
- Сложные шкалы 1–10 для тонких параметров
- Списки из 5+ вариантов

**Что может добавиться естественно через 3–6 месяцев** (когда привычка трекать сформирована):
- «Утром делал ли пуджу?» — одна кнопка
- «Слушал лекцию сегодня?» — одна кнопка
- «Были гости / встречи?» — одна кнопка

Все расширения **только если** появляется реальная нужда и видимая ценность.

## 16. Принципы, которым следуем

1. **Автоматизация важнее точности.** Лучше «достаточно точные» автоматические данные, чем «идеальные» от ручного ввода, который умрёт через месяц
2. **Данные — твои.** Открытые API, своя база. Никаких подписок, в которых данные «застревают»
3. **Один утренний экран.** Не сложный дашборд, а самое важное за 1–2 минуты
4. **Инсайты — фоном.** Не каждое утро по абзацу. Раз в неделю-две — настоящие, выстраданные корреляции
5. **Фазы, не «всё сразу».** Минимально жизнеспособное ядро за 2 недели. Усложнение — только когда базовая версия живёт
6. **Уважение к практике.** Имя системы, формулировки, тональность — не нарушают вайшнавское пространство. Пандитджи — не учитель, не Бог, а уважаемый знаток-помощник
7. **Эволюция через обратную связь.** Если переменная не даёт корреляций — убираем

## 17. Что НЕ входит в систему

- Подробное логирование питания (CGM-сессии вместо этого)
- Счётчики джапы по кругам и тайм-кодам (Muse сам измеряет качество)
- Подробные графики и дашборды (один утренний экран)
- Нативное мобильное приложение (PWA или Telegram достаточно)
- Социальные функции, поделиться, лидерборды
- Геймификация, очки, награды
